# iOS 15 arm64e 越狱启动失败修复

## 表现与主要原因

在 iPhone 11 Pro（iPhone12,3）、iOS 15.6（19G71）上，内核利用、提权和用户空间重启的 primitives 恢复成功，但多个系统服务在启动时发生 SIGSEGV，最终因 watchdogd 约 90 秒未报到而整机重启。

主要缺陷位于 litehook 的指针分类函数 `is_pointer_to_instructions`。原代码混用了未 slide 的 section VM 地址和已加载的 Mach-O header 地址，区间上界重复加入了 image 基址。共享缓存中的数据符号地址因此可能被误判为指令地址。

`_posix_spawn_with_filter` 和 `_execve_with_filter` 是存储 hook 的数据变量地址。误判后，`_litehook_sign_if_executable` 给这些地址添加了函数指针 PAC 签名，systemhook 随后向错误签名的地址写入 hook，引发访问故障。

该判断改写来自 litehook 提交 `31b5bdd`，包含于本地使用的 `cb5c5a3`。Dopamine 上游曾在 `06f4254` 回退到 `0d9d17a`；本地移植提交 `142959b` 又升级了该依赖。此次同步保留了本地的子模块版本。

## 修复内容

- 根据加载 header 与 `__TEXT.vmaddr` 计算 image slide，用 `slide + section.addr` 统一判断指令区间；使用差值判断避免区间上界溢出。
- 修复共享缓存旧格式 image 目录字段兼容性，以及内嵌符号文件读取前未恢复文件游标的问题；补充文件指针初始化及缺失 image 的退出处理。
- systemhook 仅在 spawn/exec 两个过滤指针均非空时写入；符号缺失时回退到普通指令 hook。
- 减少 launchd 日志写入：缓存日志路径、单一写入目标、处理 EINTR/短写，不再逐行 fsync；保留限量启动及 Mach 请求诊断。
- 为 BaseBin 的 DOUIManager stub 补充 jailbreakLogPath，以支持完整构建。

## 验证结果

| 验证 | 结果 |
| --- | --- |
| 真实 iOS 15.6 Mach-O header 的代码/数据分类及区间边界 | 13 项通过；原函数可复现数据符号误分类 |
| 旧/新缓存 header × 内嵌/外部符号文件 | 4 种组合通过 |
| BaseBin 完整构建、Xcode App 构建 | 通过 |
| 安装包 CRC、包内 basebin 及重建库一致性 | 通过 |
| iPhone12,3 / iOS 15.6，关闭插件注入 | 用户确认进入系统、显示已越狱，无新增 IPS |
| 同设备开启插件注入并重启用户空间 | 用户确认成功 |

其他设备和系统版本尚未完成实测。通用地址计算没有写死 iOS 15.6 的符号地址。

## 保留的诊断行为

当前成功版本保留 `ios15-data-pac-fix-20260930` 标记。`.safe_mode` 存在时，notifyd/logd 启动跳过 systemhook 注入；开启插件注入并移除该标记文件后，两项服务恢复普通注入路径。

这些诊断条件与设备验证版本一致，后续可单独整理。修改包含 litehook 子模块提交，检出本修复时需要同步子模块引用。
